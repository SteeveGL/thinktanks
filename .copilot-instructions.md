# Thinktank Repo Instructions

> These instructions apply to Thinktank sessions only — they govern how each brainstorm session folder is created and maintained. They do **not** govern the coding agent working in this repo (e.g. repo maintenance, renames, or edits outside a session folder).

This repo is a collection of independent Thinktank sessions. Follow these rules.

## Core rules

1. **Purpose** — This repo holds multiple, separate Thinktank sessions. Each session is an isolated experiment in thinking.
2. **New session** — For each new topic, immediately create a new folder named after the topic. Do this as the first action when a topic arrives, not after the conversation ends:
   - Pick a clear, specific folder name in PascalCase (e.g. `FolderIdeas`). If a folder with that name already exists, don't add a timestamp — instead make the name more precise or detailed (e.g. `FolderIdeasBackend`) so it stays unique and descriptive.
   - Create the folder + `ReadMe.md` (session overview + links). Record the session date *inside* `ReadMe.md`, not in the folder name.
   - Write the raw thinking into `Thoughts.md`.
   - Seed a distilled `Summary.md` (the single source of truth) and update it as ideas converge.
   See the `Folder template` section below.
3. **Referencing past sessions** — You may reference previous sessions, but treat them as inspiration, not ground truth. Do not inherit their conclusions. If you want to build on or contradict an earlier session, ask first rather than silently adopting its direction.
4. **Distilled version** — Always keep a distilled, up-to-date `Summary.md` for the *current* session. Update it as the ideas converge. This is the single source of truth for what the session has concluded.
5. **No silent edits** — Never modify a previous session's folder without explicit permission. Past sessions are frozen records.

## Suggested additional rules

6. **One topic per folder** — Keep a folder focused on a single thread. Split off tangents into their own subfolder or session rather than letting them bloat the parent.
7. **Record the date inside the session** — Put the session date in the `ReadMe.md` header, not in the folder name. If a folder name already exists, make it more specific rather than adding a timestamp.
8. **Capture the raw thinking** — Keep the messy, early exploration (a `Thoughts.md` or running notes) separate from the distilled summary. The raw log is the trail; the summary is the destination.
9. **Label confidence** — Mark ideas by maturity (e.g. `🟢 solid`, `🟡 untested`, `🔴 wild`). This makes it obvious what's been validated versus what's still a hunch.
10. **Decision log** — When a session makes a notable fork or drops an idea, note *why* (a short `Decisions.md` or inline notes). Future-you will thank present-you.
11. **End each session with next steps** — Close a session with an explicit "What's next?" so the next session (or future-you) can pick up without re-deriving context.
12. **Commit and push regularly** — Commit meaningful progress as you go, and push frequently (at least once per session, more if a milestone is reached). Keep commits focused and describe the session/topic. Past sessions are frozen records, so a commit is the right moment to snapshot a session's state before moving on.
13. **No shared code, no cross-dependencies** — Sessions are independent. Don't import, symlink, or reference files *inside* another session's folder; copy intent into prose instead.

## Folder template

Sessions live at the repo root, each in its own PascalCase folder:

```
<TopicSlug>/                 # PascalCase, specific; refine if a name already exists
├── ReadMe.md             # session overview, links to Summary.md (required)
├── Summary.md            # distilled, always-up-to-date summary (required, single source of truth)
├── Thoughts.md           # raw, chronological notes (optional)
└── Decisions.md          # notable forks / dropped ideas (optional)
```
